A Summary that reads like Piopio

Today's column copies Claude's: icon rows under "Where it runs", "Context", "Results". Below are three directions with their own grammar, each drawn for Build and for Chats, then what happens to the + menu if the configuration moves here, and how the rest of the app follows.

All three stay inside grey ink: no colours, no chips, blue only for links and the needs-you dot. The personality comes from the words and the structure, not from decoration.

Three directions

  • A · Card. The session is described the way an agent already is (Does, When, Can…): a verb on the left, the answer on the right. You read it as sentences: "Works in financial_ia", "May edit files on its own", "Uses GitHub and Linear". No icons.
  • B · Log. The session as a short story on a rail, the same rail as the activity log: started, plan, what it wrote, what it committed, now. The setup folds into one line at the bottom.
  • C · Glance. Outcome first: three numbers you read in a second (what changed, room left, cost), then what it made, and the setup as a compact grid at the end because it rarely changes.

How they compare

  • A · Card is the most Piopio: it reuses the agent card's grammar, so Build, Chat, Notebook and Agent read as one family. Each answer is the control (click "edit files on its own" to change it). Weakest at showing progress over time.
  • B · Log is the most different from Claude and the best while the agent is working, but it repeats the transcript's activity lines, and the setup is one click further away, which hurts if the configuration moves here.
  • C · Glance answers "how did it go?" fastest. The big numbers are its personality but also its risk: on a chat with nothing searched they're mostly zeros.

My pick is A, with B's "now" line on top while the agent is working (one bold line: "Writing the PDF report · step 3 of 4"), which disappears when it's done.

Should the setup move here, leaving + for files?

Today the + menu mixes two kinds of things: things you attach to this message (files, a folder) and things that are true for the whole conversation (connectors, MCP, web search) or that you run (commands, skills). Three ways to split them:

1Everything in the column

+ attaches files, the column holds apps, MCP, web search, skills and a list of commands. Clean, but commands are actions, not settings: a list of them in a side panel is a catalogue you scroll, not something you use.

2State in the column, actions on /

+ opens the file picker straight away (files and folders in one panel, no menu). The column's Uses and Knows rows hold the on/off state: apps and MCP servers, web search, skills. Typing / runs a command or a skill, as today. Each place has one job: + is for this message, the column is for this conversation, / is for doing something now.

3Keep both

The + menu stays as a shortcut and the column shows the same switches. Nothing to relearn, but the same switch in two places is what makes the menu feel crowded today.

The catch with 2: with the column closed you can't see what's on. Two small fixes: the Summary toolbar icon says what's on in its tooltip ("2 apps on"), and when the model would need something that's off ("Calendar is off for this chat"), the transcript says so with a Turn on link instead of failing quietly.
