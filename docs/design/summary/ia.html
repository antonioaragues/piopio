What the column is for

The Summary mixes how a conversation is set up, what it was given, what it's doing and what it made, and leaves some of it out. This page lists everything a conversation can tell you, sorts it into five groups, decides where each thing lives in the window, and redraws the column in style A.

What goes wrong today, in short: Results mixes input (files you shared, pages it read) with output (what it wrote); Context is a meter with nothing under it; things you gave it in Build don't appear at all; and the same switches live in two places.

2 · Five groups, one question each

Nowis it busy?

What it's doing this moment, or that it's waiting on you (with a link to the card in the transcript).

Only there while something is happening; gone when it's done.

Madewhat came out?

Three verbs: Wrote (new documents and files, which open in the viewer: the artifacts), Changed (edits to files that were there, which open as a diff), Saved (commits and what waits to push; a pull request later).

A file the agent created is an artifact even in a code project; an edit is a change.

Planwhere is it going?

The checklist, when the agent keeps one. Hidden otherwise.

Contextwhat is it working from?

You gave (files, folders, @mentions, images), Follows (AGENTS.md), Remembers (notebooks and agents), Read (pages and files it looked at itself).

The meter becomes this group's header ("1% full · Compact"): it measures exactly what's listed under it.

Setuphow is it set up?

Works in (folder), On (branch or worktree), Runs on (this Mac or the cloud), Uses (apps, MCP servers, web search), Knows (skills).

For agents, also Does, When, Reaches you: for them the setup is the identity.

Spendwhat did it cost?

Cost and time, in the footer. Not a group, a total.

3 · Where each thing lives

The column is one of six places. The rule that decides is how far the thing reaches: one message, the whole conversation, every conversation.

Composerthis messageAttachments (+), and the two things you change every few turns: model and mode. Setup doesn't repeat them.
/do something nowCommands and running a skill.
Columnthis conversationThe five groups: an index of it, not the detail.
Transcriptthe storyActivity, approvals, questions. The column points into it, it doesn't repeat it.
Toolbar viewsthe detailChanges (the full diff, commit, rewind), Files (the tree), Terminal. Made's rows open them.
Settingsevery conversationDefaults. The column can only turn things off for this conversation, as today.

4 · In what order

Two ways to stack the groups. By attention (recommended): what changes and matters most on top, what's stable at the bottom, so you never scroll to see the result. By flow: setup → context → plan → made, top to bottom like a recipe; easier to explain, but the result ends up last. Switch between them in the mockups below.

Empty groups are hidden: a chat with no plan and nothing made shows Context and Setup only.

Notebooks are the one exception to the layout: their Topics list is both Plan (open topics) and Made (decided ones), and it's also how you move around, so it stays on top as it is. Context and Setup go below it.

Debates keep their draft pane: there, Made is the whole screen.

6 · What this needs from you

  • Order: by attention or by flow.
  • Model and mode out of Setup? I've left them only in the composer, since you change them every few turns. The cost: the column alone no longer tells you everything about how it's set up.
  • Wrote vs Changed in Build: new files count as artifacts (open in the viewer), edits as changes (open as a diff). Should a new code file count as written, or only documents, images and data?

What's new to build

  • App: the groups, Build's "You gave" (from @mentions and attachments), "Follows" and "Read", the Now line, Made's three verbs.
  • Engine: chats writing files (for chats' Made), and turning skills off per conversation (Knows' switches).
