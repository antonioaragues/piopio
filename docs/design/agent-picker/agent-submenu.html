Agent models: a submenu on hover

An agent row works like a macOS menu item with a submenu. Hover it and its models slide out beside it. Click it and you get the agent with the model it already shows. The chevron marks the row; it is no longer a button of its own.

Built 2026-11-21 in ModelPicker.swift (AgentSubmenu, AgentModelsMenu) · the traits on the right (“most capable”…) were left out: agents give no short trait for their models

Chosen: Claude Code · Opus 5.5

One targetThe whole row opens the submenu on hover (after ~0.1 s, so sweeping past doesn't flash it). Click picks what the row shows. The chevron is only a sign.
Placed like a menuFlush against the picker's right edge, its first model level with the row. No arrow, no title — the row it grows from is the title.
Forgiving pointerMoving diagonally toward the submenu keeps it open, even across the next agent row. It closes ~0.25 s after the pointer settles elsewhere.
Row stays litWhile its submenu is open the agent row keeps its grey highlight, so you see where the list came from.
What's insideThe agent's main models with a quiet trait on the right, ✓ on the one in use, then “Older models” folded below a line.
Keyboard→ opens it with the current model highlighted, ← or esc goes back to the row, ↩ picks, ⌘↩ picks and sets the default.

3 · Smaller fixes in the same pass

  • “Show N more variants” moves up, right under the models it unfolds, and says “variant” when there is one.
  • The agent row shows ✓ when it's the one in use, as model rows do; today that check fights with the chevron for the same corner.
  • Searching keeps today's behavior: matching models show indented under their agent, no submenu needed.

4 · The alternative I'd skip — inline

Clicking an agent could unfold its models in the list instead. It needs no second panel, but the list jumps under the pointer, the Thinking control gets pushed out of view in a 440-point picker, and it isn't what you expect from a ›. Shown for comparison only.

Building it

The submenu has to spill outside the picker's own popover, so it becomes a small borderless child panel of the popover's window, placed from the agent row's frame — not a SwiftUI .popover (that's what brings the arrow and the gap). Hover intent and the diagonal allowance live in ModelPicker; AgentModelsMenu keeps its rows.
