The + menu

  • Files or photos (⌘U) and a folder: what the + does today, split in two.
  • Commands and skills: opens the / list that already exists.
  • Connectors and MCP: toggles for this conversation, on top of the defaults in Settings. One that needs signing in again says so.
  • Web search moves here from its own composer button.
  • Add extensions opens Settings › Extensions.

Icons in the toolbar

  • Summary, Changes and Files each open the right column on that view; clicking the lit one closes it.
  • Terminal stays a drawer under the conversation, now with its own button.
  • Open in editor and ··· (rename, session tree, export) after a divider.
  • The git menu moves into Summary's branch row, so the toolbar has one kind of thing: views.

Summary column

  • Where it runs: This Mac, the folder, the branch (its git menu), the permissions.
  • Context: the meter, what fills it, Compact.
  • Connectors and MCP: how many are on, which need you.
  • Checklist: the agent's todos.
  • Results: files changed, commits, pages and documents it wrote. Each opens its diff or viewer.
  • The cost at the bottom, as today.

The same toolbar and column everywhere, each with what that kind of conversation has.

What it takes

  • App only: the toolbar icons, the Summary column built from what the app already has (folder, branch and git menu, permissions, context, todos, changes, cost), and the + menu for files, folder, commands, web search and extensions.
  • Engine: connectors and MCP servers on or off per conversation. Today both are app-wide: a connector's "use in chats" flag and an MCP server's "In Chat" switch. A conversation would keep its own list in sessions.configure, and Build sessions would filter pi's MCP servers by it. Also a "needs signing in again" state per connector account, and a list of what fills the context.
  • Results: Build has files and diffs today. Commits, written pages and exports need to be recorded as results as they happen, per session.

In what order

  1. Toolbar and Summary in Build sessions. App only, with today's data. The inspector becomes the column's Changes and Files views.
  2. The + menu with files, folder, commands, web search and extensions, in every composer.
  3. Connectors and MCP per conversation. The engine change, then the submenu and the Summary row.
  4. Results beyond files, then the column in Chat, Notebooks and Debates.

Decisions for you

1. Does a toggle in the + menu change only this conversation, or the default too?Recommended: only this conversation. Settings stays where defaults live; the menu is for "not here" or "here too".
2. Should the Summary column open by itself?Recommended: remember per session, as the inspector does now, and open by itself the first time a session changes files.
3. Where does the git menu live?Recommended: in Summary's branch row, with Commit… also in Changes. The toolbar only switches views.
4. "Where it runs" before there is a cloud option?Recommended: show "This Mac" anyway. It's true today and leaves room for the choice in Q4 of the roadmap.
