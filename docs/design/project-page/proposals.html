The project page

Two things: how a project can take folders you already have on this Mac, and three ways to show a selected project without the Conversations · Board · Settings tabs.

Folders as context

A project keeps its own folder (in ~/Piopio, or the one you opened) and can link other folders: your thesis in Documents, a reference repo, a folder of PDFs. Nothing is copied or moved; the project just knows they're part of it. Each linked folder is Read only by default, or Can edit.

WhatHow it works
Add one"Add folder…" where the project lists its folders (every design below has that list), or drag a folder from Finder onto the project's row in the sidebar.
Read onlyAlready possible: Piopio lets a conversation read anywhere. What's new is that every conversation in the project is told the folder is there, and @ finds its files.
Can editThe folder joins the project's sandbox and permissions, so edits there follow the same mode (Ask, Auto-edit…) as the project's own folder, instead of asking every time.
One conversation onlyThe box's + gets "Add folder…": that conversation reads it, the project doesn't keep it. Same as attaching a file, but a whole folder.
Notes and instructionsStay in the project's own folder (AGENTS.md, NOTES.md), never in a linked one, so linking a repo doesn't change it.
A

A project home, in two columns

One page, no tabs. On the left, the box to start a conversation here and the conversations under it. On the right, a quiet column with what the project is: instructions, notes, folders, who works here, routines. A team's board shows as one line above the conversations that opens the full board. Settings that are rarely changed (permissions, checks) sit behind the … menu.

A1 · With a team, a line appears above Conversations: "Board · 2 doing · 1 in review · 5 done Open ›", and Who works here shows the team. The … menu holds Permissions, Checks, Reveal in Finder and Remove.

Good
  • Everything about the project is visible at once, without hunting through tabs.
  • Starting a conversation is the first thing on the page, like every other New.
  • Folders have an obvious home, next to the instructions they work with.
Costs
  • The right column is a second place for things that also live in a session's Summary panel.
  • The Board loses its tab; with a busy team, one line may feel too small, and the full board is a click away.
B

Quiet tabs, with a Context tab

Keep separate views, but make them text: the name large, and under it Conversations · Context · Board · Settings in plain type with a thin underline on the current one, like a document's sections rather than a segmented control. A new Context tab gathers what conversations here are given: the folders, AGENTS.md and NOTES.md, edited in place. Settings keeps only who works here, routines, permissions and checks. Board appears only with a team.

B1 · The Context tab, while a folder is dragged from Finder onto the project in the sidebar (B, A and C all accept that drop). Conversations is a hairline list like A's; Settings keeps its current sections minus instructions and notes.

Good
  • The smallest change to how it works now; only the look changes, plus one tab.
  • "Context" is one clear answer to "what does every conversation here know?"
  • Room to edit AGENTS.md in place instead of opening a file row.
Costs
  • Still tabs: you have to know which one hides a thing.
  • Starting a conversation is a button, not the box: one more step than the rest of the app.
C

The project is its start page, with a Summary panel

No project page at all. Clicking a project opens its New conversation page, the same one its + opens, with the project's latest conversations listed under the box to pick up. Everything about the project lives in the Summary panel on the right (⌘I), the one sessions and chats already have: folders, instructions, notes, who works here, routines, and Board when a team works here.

C1 · The line under the box counts the linked folders, so you see what a new conversation will be given before you send. With a team, the panel starts with "Board · 2 doing · 1 in review ›", which opens the board full width; Routines › opens its list in the panel.

Good
  • One less kind of page: a project, a session and a chat all read the same, with the Summary panel for "what is this".
  • Clicking a project does what you most often want, start or pick up a conversation, instead of showing a page about it.
  • The folders are shown where a new conversation is about to start, and the line under the box says how many it gets.
Costs
  • The project's + and its row now open the same page; the + becomes a shortcut, not a different place.
  • The Summary panel has to be open to see the project's details; a first-time user may not look there.
  • The Board is a step further away for teams.

My pick

C. It removes a page instead of redesigning it. Sessions and chats already use the Summary panel for "what is this", and a project would too. Clicking a project lands where you'd go next anyway: the box, and the conversations to pick up. Linked folders show where they matter: in the panel, and counted in the line under the box before you send.

A if you want a project to feel like a place with its own home page. B if you'd rather keep the views and only make them quieter; its Context tab is also the easiest way to ship linked folders first.

Whichever you choose, linked folders are the same piece of work: a list on each project (Read only or Can edit), a line in every conversation's prompt naming them, @ search across them, and editable ones added to the sandbox and the permission rules.
