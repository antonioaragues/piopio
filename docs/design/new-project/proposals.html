Adding a project

Keep the + on Projects. It's the only visible way to add one: ⇧⌘N, the File menu and the palette are invisible, and "New project…" is inside the box's popover. The page it opens is the problem. Opening a folder you already have is the most common case, but it's a small link at the bottom. A large empty instructions box comes first, and Who works here reads as a sentence with nothing to click.

What all three do: both ways in are first-class, a new folder in ~/Piopio or one you already have (with the git repos and pi folders Piopio already finds on this Mac). Instructions stop being a required-looking box: AGENTS.md gets written from what you say, or later. Who works here is a plain selector (Piopio, or a team) that defaults to Piopio. Everything ends in the project's New conversation, as today.

A

A menu, and the name in place

No page at all. The + opens a short menu: New project, Open folder…, and the folders this Mac already has. New project adds a row to the sidebar with its name selected, like a new folder in Finder; Return makes ~/Piopio/Name and opens its New conversation. Instructions come later, from a line on that page.

A2 · You type the name in the sidebar and press Return; the folder exists, and its New conversation opens. Esc cancels and nothing is made. The line under the box offers the instructions (AGENTS.md); Who works here is in the project's Settings.

Good
  • The fastest: two keystrokes and a name. No page to read.
  • Opening an existing folder is one click from the +, with the likely ones listed.
  • Feels like the Mac (Finder, Notes, Mail all name a new folder in place).
Costs
  • Choosing a team at creation moves to Settings. That's fine for most people; worse for anyone starting a project for a team.
  • Continue in › New project needs a different flow: there's no sidebar row to rename from there. It would use the same menu, then the name sheet.
B

The first message makes the project

The + opens the New conversation page, the same one as every other New, in "new project" mode. The name is the title, and the box asks what the project is about. Sending makes the folder, writes AGENTS.md from that message and starts the first conversation. Folders you already have are listed underneath, so opening one sits on the same page.

B1 · "Piopio" in the bar is Who works here (Piopio, or one of your teams). With nothing typed, ⌘↩ makes the project empty. Clicking a folder below opens it as a project and turns the page into its New conversation, keeping what you typed.

Good
  • The same page and box as every New (spec 18 §16): one place to learn, and Plan, permissions, the model and attachments work as everywhere.
  • No empty instructions box: you describe the project the way you'd start talking about it.
  • Both ways in are on one screen, with the folders you'd likely pick.
Costs
  • Writing AGENTS.md from a message is new engine work (a drafted file you can review, as agents do when they set themselves up by talking).
  • One page doing two things: if the folder list grows long, it competes with the box.
C

Two doors, side by side

Today's page, rebuilt around the choice it hides: Open a folder and Start a new one as two equal halves. The new side is a name field and where it goes; instructions and team fold away under one line each. The black button follows the side you're on.

Costs
  • Still a form to fill before anything happens, which spec 18 tries to avoid ("you always start by writing").
  • Two cards is more chrome than grey ink usually allows.

My pick

A, the menu, with B's line for the instructions. Most projects start from a folder you already have, and the menu gets you there in one click with the likely folders listed. A new folder only needs a name, typed where the project will live. Instructions are better written once there's a conversation to write them from, so a line on the project's first page offers them. A is also the least to build: the folder scan, Open folder and creating ~/Piopio/Name all exist.

Choose B if you want New to stay one page for everything, and are happy to have the engine draft AGENTS.md from the first message. C is the safe redesign if you'd rather not change the flow at all.
