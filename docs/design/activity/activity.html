The activity line, as a short log

What the agent did before it answers (its thinking, the files it read, the commands it ran) should read as one quiet line that opens into a short log, in the order it happened. Today it reads as several things stacked on top of each other.

What feels off now

  1. The line mixes text and a pill. The file name sits in a grey box, which breaks the sentence and leaves a gap before the comma ("Thought , read").
  2. The order doesn't match. The line says read, then ran; the list underneath shows Ran first, then Read.
  3. Thinking shows up twice and too loud. "Thought" is in the line and again as its own row, open by default, at almost answer size, behind a thick rule. It reads like part of the answer.
  4. Commands show their noise. cd /Users/…/financial_ia && takes the space and the middle of the command gets cut.
  5. A blue "Open" competes with the answer, on every file row, all the time.

The proposal

  • One line, one voice. "Thought for 4s, read documento-random.md, ran a command ›". Plain text in the quiet grey; the file name is just a shade darker, with no box. The chevron points right and turns down when open. Edits keep their green +N.
  • Opened, it's a log in the order things happened. A thin rail on the left with a small glyph per step (thought, read, ran, edited, searched). Each step is one row: verb, object in mono, and on the right what you'd want to know at a glance (how long, how it ended).
  • Thinking becomes a step, not a block. "Thought for 4s", then the first two lines of it in the same small grey, with "Show all". No rule, no second disclosure, never at answer size.
  • Commands show what they do. A leading cd <project> && is dropped (it's where the session already is; a different folder shows as "in other-folder" on the right). Long commands cut at the end, not the middle. Clicking opens the full command and its output, with the exit code.
  • Actions appear on hover. Open (a file) and Copy (a command) show at the right of the row only while you point at it, in grey.
  • Working and waiting stay on the line. "Running python3 -c …" with a small spinner while it runs; "Waiting for you" with the blue dot when it needs approval, as today. A failed command shows a red ✕ in the log and "1 failed" on the line.
