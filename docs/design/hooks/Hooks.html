Your hooks

Commands Piopio runs at fixed moments, every time, without the model deciding: before a tool (and able to stop it), after a tool, and when a turn ends. A rule in AGENTS.md asks; a hook makes sure (PAR6).

Round 2, staying close to pi: in pi a hook is an extension (its docs list permission gates and path protection as extension examples). So each hook you make is a small pi extension file, written from a sentence. The pi CLI runs the same files; a project's travel in its .pi/extensions/. Claude Code's hooks come in by import, not as the format.

1 · Making one: a sentence that writes an extension

Settings › Extensions › Your hooks, beside Your skills. You fill in a sentence; Piopio writes the extension file pi loads, with the sentence on its first line so it can read it back.

b

The file it writes (sketch)

// Piopio hook · After Piopio edits or writes a *.swift file, run swiftformat "$FILE" // Made in Piopio (Settings › Extensions › Your hooks). The line above is how Piopio reads it back; // change the code and it opens as code instead. import { execFile } from "node:child_process"; import type { ExtensionAPI } from "@earendil-works/pi-coding-agent"; const TOOLS = ["edit", "write"]; const FILES = /\.swift$/; const COMMAND = 'swiftformat "$FILE"'; export default function (pi: ExtensionAPI) { pi.on("tool_result", async (event, ctx) => { const file = String((event.input as { path?: string }).path ?? ""); if (!TOOLS.includes(event.toolName) || !FILES.test(file)) return; const failed = await new Promise<string | undefined>((done) => execFile("/bin/sh", ["-c", COMMAND], { cwd: ctx.cwd, timeout: 60_000, env: { ...process.env, FILE: file } }, (error, _out, err) => done(error ? err || String(error) : undefined))); // Failed: the model is told, in the tool's result. if (failed) return { content: [...event.content, { type: "text", text: `Your hook swiftformat failed:\n${failed}` }] }; }); }
  • Three templates, one per moment: before (tool_call, can stop it), after (tool_result), turn ends (turn_end, can ask for another turn, three at most).
  • Self-contained: no Piopio package to install, so the pi CLI runs it on its own.
  • Saved as ~/.pi/agent/extensions/hooks/<name>.ts, or the project's .pi/extensions/hooks/.

The same whichever way

  • A command gets $FILE for the file and the call as JSON on its input; a Before hook whose command exits 2 stops the tool, and its message goes to Piopio.
  • Hooks run in Build sessions and chats with a project; never in agents' scheduled runs unless their project allows them.
  • A hook has 60 s by default; one that hangs is stopped and reported, never blocks the turn for good.
  • Later: /learn proposing "make this a hook" when you correct the same thing twice: the model writes the extension, as pi recommends.
