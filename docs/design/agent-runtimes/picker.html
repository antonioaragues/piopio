Model picker and composer chip

Two fixes: the chip names a model the same way whether a model provider serves it or an agent runs it, and the picker tells “Opus through OpenRouter” apart from “Opus in Claude Code” at a glance.

Mockup for review · nothing built · follows docs/design/grey (plain text selectors, 16pt outline glyphs, no badges)

1 · The chip: always “model · who runs it”

Today OpenRouter reads model · provider and Claude Code reads agent · model. One order for both: the model first, then who runs it. An agent gets one extra thing, a small terminal glyph before the name. It's the same glyph that marks agents in the picker and in Settings, so you learn it once.

3 · Switching in a conversation with messages

Picking an agent in a conversation that already has messages switches it (spec 31, phase A2, built together with the picker). The conversation says so with one line. The agent starts its own session from a summary of what came before; the earlier tool calls stay with whoever made them. Switching back works the same way.
