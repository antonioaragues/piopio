Coding agents in Piopio

Claude Code, Codex and Gemini CLI as things you pick in the model picker. When you pick one, it runs the whole conversation on your own plan, and Piopio stays the window around it.

Proposal and mockups · 20 Nov 2026 · nothing built yet · all model names and numbers are sample data

The rule: a conversation runs on Piopio's agent or on one of yours. It's one choice, made in the picker. Picking “Gemini 3 Pro · Gemini CLI” doesn't put a pi model in front of Gemini. Gemini CLI receives your messages, runs its own tools and answers. Piopio draws the transcript, asks you for approvals, keeps checkpoints, and gives the agent its own tools (memory, connectors, browser) through MCP. The current task handoff to Claude Code or Codex stays for conversations that run on Piopio's agent.

What T3 Code does

T3 Code is a control panel for agents and has no agent of its own. “It is a local control plane for those agents, not a new model or a hosted coding agent.”

  • Every provider is a CLI run as a subprocess. An adapter per provider turns its protocol into T3's events. Codex runs through codex app-server, Claude Code through the Claude Agent SDK, and Antigravity, Grok and others through ACP. The provider's own loop and tools do the work.
  • It uses your own sign-in. T3 doesn't sell tokens. You sign in with each CLI (claude auth login, codex login). If a binary isn't on the PATH, you set its path under Settings › Providers.
  • Settings › Providers shows each provider's installed version, sign-in state, plan and an on/off switch. Each has its own binary path, arguments and environment, and you can add a second instance for another account.
  • The picker groups models by provider and includes reasoning level and a Fast switch. You can switch provider in the middle of a thread. The thread marks where the change happened, the context carries over, and the old provider's tool calls and reasoning stay behind.
  • The composer holds model, reasoning, permission mode (Supervised, Auto-accept edits, Auto, Full access) and plan mode. Modes a provider doesn't support fall back to Supervised. Approvals show inline with Approve and Decline.

Gemini isn't on T3's built-in list. Google's agent there is Antigravity. Sources: README, AGENTS.md, Flavio Copes' deep dive. T3 is in 0.1.x beta, so details change quickly.

Where Piopio is different

T3 is only a shell around other people's agents. Piopio already has its own agent, with memory, connectors, the browser, computer use, side conversations, agents and automations. So the question isn't whether to replace it. The question is how both kinds share one picker, one transcript and one approval tray. The answer is the same in each case: the conversation keeps every Piopio surface, and the agent changes underneath it.

Under the hood

  • One new runtime, AcpRuntime. The engine already has a Runtime interface “whatever harness backs it” (runtimes/runtime.ts). An ACP client implements it once for all three: Gemini CLI speaks ACP natively (gemini --experimental-acp, present in the 0.27.3 on this Mac), Claude Code through Zed's claude-agent-acp adapter, and Codex through codex-acp. Any other ACP agent (OpenCode, Kiro…) can be added later without new code.
  • Model refs don't change shape: { provider: "agent:gemini", id: "gemini-3-pro" }. sessions.ts picks AcpRuntime when the provider starts with agent:. Reopening a conversation calls the agent's session/load.
  • Detection reuses external-agents.ts (it already finds claude and codex on the short app PATH), plus gemini, the version and the sign-in state. providers.list returns them as a new kind, “agent”.
  • Piopio's tools as MCP: a small stdio MCP server inside the engine exposes memory, connectors, browser and computer use. It's passed in session/new, so an agent conversation keeps them.

Open questions

  • Bundle the Claude and Codex ACP adapters with the app, or install them on first use? (Gemini needs nothing.)
  • Plan limits: when the agent hits its plan's limit, show a notice with “Use another model”. Never move to credits without asking (spec 29).
  • Terms: Piopio drives the CLI you installed and signed in to, the way Zed and T3 do, and never reads or reuses its tokens. Worth reading each provider's current terms before shipping.
  • Notebooks: the organizer that inserts headings is Piopio's own. Does it keep running on a model while the conversation runs on an agent, or is it off there?
