# Handoff: Side Conversation Card (option 1a)

## Overview
An inline card that appears in the chat stream, after the assistant's "Thought ›", when the assistant detects that the user's request is a separate task (example: "vamos a diseñar una app para citas" while working in an unrelated repo). The card offers two choices: open the task in a new side conversation, or continue in the current one. Opening the side conversation is the primary action. After the user chooses, the card collapses into a compact row.

## About the Design Files
`Side Conversation Card.dc.html` is a **design reference built in HTML**. It is a prototype of the intended look and behavior, not production code. Rebuild it in the target codebase's existing environment (React, Vue, SwiftUI, etc.) using its own components and patterns. The file also contains options 1b, 1c, 2a and 2b; **implement only 1a** (section `#1a`).

## Fidelity
**High-fidelity.** Colors, typography, spacing and copy are final. If the codebase has equivalent tokens (neutrals, accent blue, radii), use them.

### State 2 — Opened (after the primary action)
A compact row replaces the card.
- Bg `#FFFFFF`, border `1px solid #E7E5E0`, radius `12px`, padding `12px 14px`, row, gap 12px
- Icon chip 28×28, radius 8px, bg `#EEF1FB`, glyph `#3C5BD6` 13px
- Text column (gap 2px): title 14px/500 `#1F1E1C`; subtitle 12px `#8A8780`, **"Side conversation abierta · se ha movido el brief"**
- Right side: link **"Ir ↗"**, 13px/500, padding `6px 10px`, radius 8px, bg `#F3F2EF`, no underline. It navigates to the new conversation.

### State 3 — Continue here (after the secondary action)
The card is removed and replaced by the line "Continuando en esta conversación…" (13px `#9A978F`). The assistant then carries on in the same thread. In production this line can be dropped and the assistant's normal reply shown directly.

## Interactions & Behavior
- **Primary** → create a new conversation seeded with the title and the full brief. The suggestion card becomes the State 2 row. Optional: navigate straight to the new conversation; the row keeps a way back.
- **Secondary** → dismiss the card and continue in the current thread (State 3).
- The decision is persistent: when the conversation is reloaded, the row shows the state that was chosen.
- Transitions are not specified. A short height and opacity crossfade (~150–200ms ease-out) between states is recommended.
- Keyboard: both buttons are focusable and use a visible focus ring from the codebase.

## State Management
- `status: 'idle' | 'opened' | 'here'` per suggestion message
- `title: string`, `brief: string` (generated by the assistant)
- `sideConversationId?: string` (set after it is created; used by the "Ir ↗" link)
