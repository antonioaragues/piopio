Editing instructions and memory

In the project settings modal, Instructions (AGENTS.md) and Memory (NOTES.md) each get two ways to edit: Edit opens the file inside the modal, and an arrow opens it in your editor (the one Piopio already uses for "Open in…": Zed, Cursor, VS Code, or TextEdit when there's none). Either way it's the same file in the project's folder.

1 · Two rows in the modal

Each row says what the file is for, shows its first line, and has Edit plus the ↗ arrow. Memory also says how much of it every turn reads. If a file doesn't exist yet, the row reads "None yet" and Edit creates it.

2 · Edit inside the modal

Edit turns the modal into the file: it widens to 760 and the header becomes ‹ Tesis · Memory with the file name. The text is plain markdown in a monospaced font, with headings in bold and list marks in grey, nothing hidden. A line under the header says what the file does. It saves as you type (half a second after you stop), like the rest of the modal; Undo all puts back what was there when you opened it. ‹ Tesis or Esc goes back to the settings.

"Done" here goes back to the settings (it's the modal's one action). The meter only appears for Memory; Instructions shows "Saved" and Undo all. For Instructions the hint reads: "What every conversation in Tesis is told before it starts. Who it's for, what matters, how to answer."

3 · When the file changes elsewhere, or grows too long

Memory is written by conversations too, and you may have it open in Zed. While the editor is open, Piopio watches the file. If nothing is typed here, it simply reloads. If you've typed and the file changed, a bar asks which to keep, instead of writing over a line a conversation just added. When memory passes what a turn reads, a dashed line marks where reading stops.

"Use theirs and mine" keeps the lines the file gained and applies your edits on top; conversations almost always add lines, so this rarely conflicts. When it can't (you both changed the same line), only "Keep mine" and "Reload" are offered. "Keep mine" writes your version. Lines past the limit are grey and kept; Piopio never deletes them for you.

4 · Behavior

WhatWhat happens
EditOpens the file in the modal. If it doesn't exist, creates it (AGENTS.md with the project's name as title, NOTES.md with "# Notes") and puts the cursor at the end.
↗ Open in <editor>Opens the file in your editor (Settings › Open files in), or the default app for .md. The modal stays open; if you also have Edit open, it reloads when you save there.
SavingHalf a second after you stop typing, and when you leave the editor. The footer says Saved, Saving… or why it couldn't.
Undo allPuts back the file as it was when you opened it here. ⌘Z works line by line as usual.
A conversation is runningIt reads the file at the start of each turn, so your change applies from its next turn. Nothing is restarted.
CLAUDE.md instead of AGENTS.mdThe row edits the one the project has (it says which); Piopio doesn't create a second file.
KeyboardEsc goes back to the settings; ⌘↩ or Done too; ⌘O opens in your editor.

For you to decide

  1. Save as you type, or a Save button? I'd save as you type, like the rest of the modal and like Notes or Bear, with Undo all as the way back. A Save button is safer if you'd rather review before a conversation reads it.
  2. Plain markdown, or rendered? I'd keep it plain with light styling: these files are read by models, and what you see is exactly what they get. A rendered view could come later as a toggle.
  3. The arrow, or a menu? One arrow is enough while there's one editor. If you use several, it could become "Open in ▾".
