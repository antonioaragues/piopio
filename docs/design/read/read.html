Read: what the answer is based on

Read lists what the agent took in from outside the conversation, so you can open it and check. Chats and projects use the same definition. A project just has more sources.

Two ways to draw it. Switch between them and between a project and a chat above the window. Click Read and its groups to fold them.

What goes in Read

GroupWhatClickWhere
You gaveFiles attached to a message, and paths you @mentionedA file opens in the preview, a folder in FinderBoth
FilesWhat it opened with its read tool, first read firstOpens in the preview, on FileProjects
PagesPages it fetched, and the sources its web searches returned (the search's summary is written from them)Opens in the browserChats, and agents with web tools

Not in Read: commands are actions, not sources, so they stay in the timeline (and in Background while they run). What it changed is the Changes block. AGENTS.md goes under Setup. Skills have their own block.

One limit: a file it read through a command (cat, grep) doesn't show, because we can't tell reliably from a command what it read. Pi's read tool is how it normally opens files.

The two options

  • A · One list. The chat's Read today, extended: a subheading per group, six rows and then "and N more", and at the end, in a project, "Show in Files ›" for the tree. Easy to scan when it read a handful of things; long when it read forty.
  • B · A fold per source. Open, Read shows one row per group with its count. Each one unfolds in place. Files come grouped by folder, so thirty-eight files are six lines. More clicks for a short conversation, but it stays short however much it read.

In both, the row folds to a line like "2 you gave · 9 files", and whether it's open is remembered, as with the chat's Read today. A click never takes you to another panel; only the explicit link does.
